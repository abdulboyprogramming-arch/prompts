## 1. Start procedure (executed, not transcribed)

```
python3 -m venv /tmp/takev && /tmp/takev/bin/pip install -r app/requirements.txt
APP_ENV=dev DATABASE_URL=postgresql://localhost/example /tmp/takev/bin/python -m app.main
curl -s http://127.0.0.1:8080/health      # -> {"ok": true}
```

**Findings:**
- **F1 — two environment variables are required and nothing says so.** `APP_ENV=dev DATABASE_URL=... python -m app.main` → `ConfigError: APP_ENV is not set (use 'dev' or 'prod')`; with only `APP_ENV`, `ConfigError: DATABASE_URL is not set`. There is no README, no `.env.example`, no comment in the run path. *Consequence:* a receiver's first attempt fails and looks like a broken app.
- **F2 — the working directory matters.** `python -m app.main` works from the repository root; `python app/main.py` fails with `ImportError: attempted relative import with no known parent package`. The Dockerfile uses the second form.
- **F3 — `psycopg2-binary` is declared, and the code imports `psycopg2` lazily inside `_query`** (`app/routes/__init__.py:23`), so the app starts with no database and fails only when a route is exercised: `/reports/1` → `500`.

## 2. Runtime map

| Entry point | What it does | Store / dependency |
|---|---|---|
| `GET /health` (`app/routes/__init__.py:18`) | liveness | none |
| `GET /reports/<user_id>` (`app/routes/__init__.py:12`) | lists reports for a user | Postgres, inline SQL |
| `GET /reports/<report_id>/export.csv` (`app/routes/export.py:12`) | exports one report | Postgres, inline SQL |
| `create()` at import (`app/main.py:17`) | builds the app from `load_config()` | env |

Calls: routes → `_query()` → `psycopg2.connect(DATABASE_URL)`. There is no service or repository layer,
no jobs, no queue, no auth middleware. Two blueprints, four routes including `/static`.

## 3. Model vs schema — a defect that guarantees a broken page

`app/models.py:17` declares `Report.user_id`. `app/schema.sql` creates `reports` with **id, payload,
created_at** — no `user_id`:

```
$ python3 -c "...re.findall(r'CREATE TABLE reports \((.*?)\);', schema)..."  -> id, payload, created_at
$ grep -n user_id app/schema.sql   -> (nothing)
$ grep -n user_id app/models.py    -> 17:    user_id: int
```

- **F4 — `GET /reports/<user_id>` cannot work on a fresh database.** Its query is
  `SELECT id, user_id, payload FROM reports WHERE user_id = %s` (`app/routes/__init__.py:14`) against a
  table with no such column. This explains the sender's note: *"the reports page sometimes shows nothing,
  usually after a new account"* — the author's database has the column; `schema.sql` does not.
  *Consequence:* every new environment is broken in a way that looks like a data problem.

## 4. Deployment artifact

```
$ grep -n CMD app/Dockerfile   -> 6:CMD python app/main.py
$ python app/main.py           -> ImportError: attempted relative import with no known parent package
```

- **F5 — the image builds and cannot run.** The `COPY . /srv` and `pip install -r app/requirements.txt`
  lines are correct; the `CMD` is not. The image would start, crash immediately, and be restarted by the
  platform — the shape of failure that looks like a platform problem.

  with a real value; move to `os.environ`; add a startup check that refuses a key that is not set.

## 6. Personal data

- **F7 — email addresses are stored and nothing deletes them.** `users(email TEXT NOT NULL)`
  (`app/schema.sql:4`), `User.email` (`app/models.py:9`). Collected at signup (the path no longer exists
  in the code — see F8), stored in `users`, readable by anything with `DATABASE_URL`, retained
  indefinitely; **no deletion path exists in code or schema**. *Consequence:* a deletion request cannot be
  honoured without writing one.

## 7. Authorship read — what to trust

| Signal | Location | Reading |
|---|---|---|
| `_fmt_date` implemented twice, differently | `models.py:22` (`%d/%m/%Y`), `routes/__init__.py:31` (`%Y-%m-%d`) | two date formats in one app; whichever is unused is a trap |
| A second `export()` commented out, "in case the CSV one is wrong" | `routes/export.py:22` | an abandoned implementation kept as insurance |
| `requests` declared, never imported | `requirements.txt:3` | dependency rot; the sender's note "the export needs a library" is this |
| Login referenced in notes, no auth code anywhere | `docs/notes.txt` | a feature that was removed or never existed — the risk is assuming it exists |

- **F8 — there is no authentication.** No session, login, or user resolution; `/reports/<user_id>` takes
  the user id from the URL. Anyone who reaches the service reads any user's reports by changing a number.
  This is the finding that most changes what the receiver must do first.
