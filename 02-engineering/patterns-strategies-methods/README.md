# Patterns, Strategies & Methods System

**Status:** Skeleton — 7 stage outlines (skeleton 7). The stages name a sensible sequence but lack the evidence rules, verification, and failure handling that this library requires of `operational`. Treat the system as a plan, not a procedure; see [`_meta/ROADMAP-AND-BACKLOG.md`](../../_meta/ROADMAP-AND-BACKLOG.md).
**Entry Point:** [`P07-Orchestrator/P07-Patterns-Strategies-Orchestrator.md`](P07-Orchestrator/P07-Patterns-Strategies-Orchestrator.md)

A structured system for discovering, evaluating, improving, or inventing software design patterns, architectural strategies, and development methods.

Use this when you need to:
- Identify the right pattern for a recurring problem
- Improve an existing approach used in a codebase
- Invent or adapt a strategy for a new class of problems
- Document a method so it can be reused by a team

## Stages

| ID | Prompt | Purpose |
|----|--------|---------|
| PS-P01 | Context & Goals | Understand the domain and what “better” means |
| PS-P02 | Problem Analysis | Deeply characterize the recurring problem |
| PS-P03 | Existing Patterns Survey | Research known patterns and current approaches |
| PS-P04 | Ideation & Adaptation | Generate or adapt candidate patterns/strategies |
| PS-P05 | Evaluation | Compare candidates against quality criteria |
| PS-P06 | Specification & Guidance | Produce a clear, usable description of the chosen approach |
| PS-P07 | Master Orchestrator | Coordinates the process |

## Principles

- Start from a real, recurring problem, not from a desire to create a pattern.
- Prefer adapting proven patterns over inventing new ones when possible.
- Make forces, trade-offs, and applicability explicit.
- Output should be usable by practitioners.
