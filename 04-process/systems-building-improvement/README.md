# Systems-Building & Improvement Process

**Status:** Skeleton — 8 stage outlines (skeleton 8). The stages name a sensible sequence but lack the evidence rules, verification, and failure handling that this library requires of `operational`. Treat the system as a plan, not a procedure; see [`_meta/ROADMAP-AND-BACKLOG.md`](../../_meta/ROADMAP-AND-BACKLOG.md).
**Entry Point:** [`P08-Orchestrator/P08-Systems-Building-Orchestrator.md`](P08-Orchestrator/P08-Systems-Building-Orchestrator.md)

A multi-stage system for improving or building socio-technical systems: engineering workflows, delivery pipelines, operational processes, internal platforms, and similar “systems of work.”

This is broader than a single codebase refactor. It addresses how work flows, where friction accumulates, and how to design better systems around people, tools, and feedback loops.

## Stages

| ID | Prompt | Purpose |
|----|--------|---------|
| SB-P01 | Context & Scope | Understand the system of work and stakeholders |
| SB-P02 | Current System Map | Document how the system actually works today |
| SB-P03 | Desired Outcomes | Define measurable improvement goals |
| SB-P04 | Diagnosis | Identify bottlenecks, failure modes, and leverage points |
| SB-P05 | System Design | Design interventions and target-state changes |
| SB-P06 | Implementation | Apply changes incrementally |
| SB-P07 | Evaluation | Measure results and adapt |
| SB-P08 | Master Orchestrator | Coordinates the full process |

## Principles

- Map reality before redesigning it.
- Optimize for leverage, not local busywork.
- Prefer small safe-to-fail interventions when uncertainty is high.
- Make feedback loops visible.
- Account for people, incentives, and operational constraints—not only tools.
